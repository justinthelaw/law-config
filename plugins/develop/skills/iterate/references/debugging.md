# Scoped incident diagnosis

Use for a selected local, staging or live failure. Diagnosis permits bounded reads within existing access and scope; it does not authorize production writes, restarts, deployments, credential changes, cluster configuration or integration installation. Apply the shared review checkpoints to the diagnostic result; a code repair reuses Iterate implementation requirements and existing authority.

1. Establish impact, expected/actual behavior, environment and occurrence window. Ask only for a consequential missing target or decision; continue independent safe analysis. Distinguish a product defect from an infrastructure/access failure.
2. Identify the actual running artifact and relevant changes using [runtime identities](../../upgrade/references/runtime-contracts.md). A source SHA or green CI alone does not identify the deployed process. Preserve unknown or conflicting identities.
3. Gather the smallest useful authorized evidence slice. Use existing native tools for selected Sentry events, CI runner/job logs, Kubernetes workload logs/events or supplied files when available. Bound target, time range and result volume before reading; do not scan unrelated projects or namespaces. Missing access is an evidence gap, not permission to install, connect or broaden scope.
4. Follow [validation evidence](validation.md) for private logs, redaction and untrusted output. Record source/query, environment/artifact identity, original timestamps/timezones, capture time and correlation IDs. Correlate across sources; distinguish clock skew, collection delay and missing records instead of silently imposing an order. Never paste credentials or full incident logs into public reports.
5. Form falsifiable hypotheses and look for disconfirming evidence. Use captured records or safe reproductions within authorized local/staging scope; do not replay mutating production requests as a diagnostic shortcut. Separate observations, supported causes and unresolved alternatives. Bounded retries require new evidence of a transient failure.
6. Return impact, cause/confidence, supporting evidence, missing evidence and next gate. When repair is already authorized, hand the bounded target and reproduction to Iterate implementation, then validation and authorized publication. Otherwise finish findings-only; do not infer repair or mitigation authority from urgency.

An optional evidence source needs only the selected target, environment, time/query bounds and existing read authority. Its result supplies provenance, identity, timestamps/correlation and bounded redacted evidence, or an explicit limitation. No vendor, connector or always-on service is required. Use other authorized evidence when a source is unavailable; do not claim a root cause that depends on the missing source.
