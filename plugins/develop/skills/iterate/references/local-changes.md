# Local changes

Iterate owns local, reversible work in one checkout, including Develop handoffs. Follow the request, steering, authority, repository instructions and user standards. Preserve unrelated edits. Let ordinary commands return their output and exit together. For longer runs, do independent work or wait for a useful result.

1. Trace the owner and its normal caller. State the design decision, behavior to preserve and a check that would fail without the fix. Reuse a current accepted brief. Follow explicit waivers within their scope, complete delegated independent plan review, or present the brief and wait before editing. Implementation authority alone does not waive review.
2. Use the wider workflow for unsettled design, unclear scope, interface design, security, concurrency, migrations, persistent data, multiple owners, destructive work, publication or explicit independent review. Honor selected skills and stronger requirements. For a bounded repair, identify the existing promise in docs or tests and verify its restoration in step 3. A new or changed public promise requires the [planning and review policy](../../develop/references/planning-and-review.md). Use one Engineering Design brief, independent intent review before edits and artifact review on the tested diff.
3. Fix the owner using existing representations. Replay the caller on base and patch. For interacting rules with a bundled reference implementation, compare short input combinations. Keep the smallest regression case. Check a working neighbor, caller suites and required checks before final review. Update affected docs, report results and gaps, and revisit changed assumptions.

Return the requested proposal or other local artifact once these checks pass. Read the owning guidance when the task needs [diagnosis](debugging.md), [refactoring](refactoring.md), [visual verification](visual-validation.md) or [publication](publication.md). Direct design and independent review use their selected entry points. A constrained resource or broad inspection request never selects a maintenance skill.
