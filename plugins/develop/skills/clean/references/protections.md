# Cleanup protections

Apply to Clean/Deep Clean, including whole-machine scope. Wider discovery grants neither removal nor privileged access.

- Protect source/locks, useful work/deliverables, `.env` variants, credentials, Codex memories, persistent application/plugin state and retained caches/bound repositories, shared dependencies, checkouts/Git metadata/worktrees/stashes/unpublished commits, current incidents, managed runtimes/mounts and services. Only disposable in-scope scratch is eligible. Task retirement and SQLite repair are separate workflows.
- Resolve retained plugin paths from known configuration/path-only bindings; never initialize, refresh or sync. Protect `CHATGPT_QA_STATE_DIR` or `$CODEX_HOME/chatgpt-question-and-answer`, its `binding.json` workspace/source paths, and `CHATGPT_QA_COORDINATION_DIR` or `$CODEX_HOME/chatgpt-qa-coordination`. Default Codex home is `~/.codex`; protect memories there and configured alternates. Preserve lexical paths/resolved aliases; uncertainty means retain.
- Exclude protected subtrees from inventories; never scan inside them. Recheck the complete protected set before each mutation. Reject parent operations, aliases, task/worktree cascades, shared Git stores or process stops affecting protected descendants/dependencies.
- Inventory names/metadata only. Native handles/processes and minimal config path fields may verify candidates; never dump secrets/private bodies. Age, old versions, absent handles or clean tracked diffs do not prove disposability. Permission failures are gaps, never authority to elevate. Revalidate identity, ownership, use and safe traversal immediately before acting.
