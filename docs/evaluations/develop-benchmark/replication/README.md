# Source-packet trials

The recovered-fixture group uses historical acceptance inputs. The replacement-fixture group uses new requirements-based tests for Tokio and runner-space. Report these groups separately.

These trials ask whether giving Codex the frozen Develop 0.9 instructions improves the code it can produce from a bounded source packet. They measure elapsed time, native token usage, and the quality of the submitted code against offline tests. Each case has one pair. The historical trials tested an agent that could inspect, edit, and test a full repository. Keep the two designs separate. [Illustrated report](../report.pdf) · [Historical cases and gold PRs](../cases.csv) · [Preregistration](https://github.com/justinthelaw/law-config/issues/71#issuecomment-6435792684)

Develop used more total context on all six tasks and finished sooner on three. Neither condition demonstrated better behavior on the primary checks. Eleven of twelve blind judgments were ties. The site maintainability reviewer preferred Control's tests for child-initiated navigation, cleanup and restored input ownership. The four recovered-fixture pairs used 23.5% more total context and 3.8% more elapsed time with Develop. The two replacement-fixture pairs used 25.7% more context and 2.9% more time. These are descriptive totals for the sampled tasks. [Per-task scorecard](../README.md#scored-source-packet-trials) · [Blind judgments](blind-judgments.json)

## Protocol

1. **Freeze and separate materials.** Match each selected upstream PR and its gold commit's first parent to the [case manifest](../cases.csv). Verify the public legacy tarball, frozen requirement and evaluator inputs. The source selector reads only the requirement and base archive. Gold, tests, prior results, condition mappings and other arms stay outside worker and reviewer inputs. Evaluator authors may know gold. A public historical task may have been memorized by the model.
2. **Build the common packet.** Rank 36-line tiles by inverse-frequency-weighted lexical matches to the requirement, with bonuses for path matches and relevance elsewhere in the same file. Include a 12-line halo and merge overlapping ranges. Use up to 90,000 bytes, allocate 30% initially to tests and fill unused space by rank. fmt uses C-family source. Later language-specific packets include code at conventional source roots or in tests, extensionless executable scripts and a root README of up to 8 KiB. Require at least 40% runnable non-test content for those later packets. Unreleased Svelte and law-config drafts failed the practical source-coverage check and were replaced before either arm saw them. The [builder](build_packet.py) reproduces the selected bytes from the public base archive.
3. **Match the model and isolate inference.** Run the signed-in Codex CLI 0.165.0-alpha.1 on arm64 using the requested model alias `gpt-6.1-sol` and medium effort. The exact provider model revision is unknown. Every phase gets a fresh ephemeral process, an empty working directory and structured output. No execution environment is attached. Disable shell, code execution, network search, skills, plugins, apps, memories and external servers. Ignore user configuration and rules. The client still delivered common user-level policy. Its content was checked before release for case or treatment hints, then held constant across arms. A synthetic model call returned a valid structured ready response, no external tools were discovered, and scored events are audited for tool use, rerouting, completed usage and procedure acknowledgment.
4. **Vary only the procedure within a pair.** Both conditions receive the same source bytes, requirement, schema, phase requests and budgets. Control uses its normal approach. Develop also receives seven frozen skill/reference files from commit `cd316824048d03e8ca1cefdf5d63a71b2f5b3021`. The assembled Develop text adds 48,714 bytes to each phase, or 340,998 bytes across seven calls before tokenization. Each phase acknowledges the supplied digest. This verifies delivery and acknowledgment. How thoroughly the model followed the text is unknown. Both arms use the same reviewer count. [Procedure and source identities](procedure.json) · [Frozen Develop files](https://github.com/justinthelaw/law-config/tree/cd316824048d03e8ca1cefdf5d63a71b2f5b3021/plugins/develop/skills)
5. **Record all seven calls.** Plan, collect two independent plan reviews, implement, collect two independent evidence reviews, and seal the artifact. Pass previous work only within that arm. The two reviewers at each checkpoint run concurrently. Neither sees the other's judgment. The implementer specifies ordered, uniquely anchored text replacements on existing files in the packet. A valid proposal can be revised once in response to material evidence-review findings. An invalid initial proposal earns no implementation credit. Preserve each released attempt, including empty artifacts and interruptions.
6. **Score actual bytes.** Replay the ordered edits against the exact base. Verify changed file bytes, make a unified diff, and normalize the submission to whole-file replacements for the evaluator. The grader verifies its received artifact digest and changed-file hashes. The frozen tests and toolchains run offline on Linux, with separate process, mount and network boundaries and a two-CPU budget. Candidate code receives only its task-owned inputs and scratch. Configuration-specific direct/descendant access checks precede scoring. Preserve a 1 GiB disk reserve, stop dependent releases at the first provider service limit, and retain partial usage as a lower bound. A non-applying patch stays in the released-arm denominator and receives no implementation credit. A missing environmental observation remains unknown.
7. **Grade independently before revealing the conditions.** Two fresh model calls each receive randomly labeled A/B patches, the neutral requirement and offline evidence. Neither receives arm identity, timing, usage, the other grader's judgment or the gold patch. One emphasizes correctness and the other maintainability and test quality. Record both preferences before joining them to the conditions. Coding style can reveal authorship, and common model family limits judge independence. The reference tests provide the quantitative behavioral evidence. [Judgments](blind-judgments.json)

All elapsed comparisons use release through sealed output. Preparation, offline evaluation and blind adjudication fall outside arm time. Native `input_tokens` includes cached reads. Uncached input equals input less cached input. Total context equals uncached input plus cached input plus output. Reasoning output is contained in output. The billing price, credits, cache agreement and actual dollar charge for the signed-in alias were unavailable. For any independently supplied prices per million tokens, the resource-cost estimate is `(uncached × input_rate + cached × cache_rate + output × output_rate) / 1,000,000`. Comparisons of total context alone cannot price a mixture of token classes.

## Offline reference and candidate evidence

**fmt.** The frozen 13-behavior C++ fixture passed 5/13 on base and 13/13 on gold. Each scored patch compiled against the original fixture. The grader ran the individual probes and attempted the native compile-test and format-test suites under GCC 13.3.0 and CMake 3.28.3. The two submitted patches each gained direct compiled-null and to_string support. Both still crashed on surrounding literals, format_to, formatted_size and three bounded-output cases. Both native builds succeeded and format-test passed. The blind packet carried the native scorer label failed_or_incomplete. A separate post-grading check of both CTest logs confirmed that compile-test segfaulted on each patch. [Observed checks](observations.json)

**Svelte.** The pinned Linux build used Node 24.22.1, pnpm 10.33.4 and 493 integrity-checked package artifacts. Eight requirement-derived observations already passed on both references. Report them separately from the two gold-derived checks that scored 0/2 on base and 2/2 on gold. The candidate grader preserves the original five native assertions from a fixed lexical subset of fork samples, checks supported changed-file syntax, and reports each assertion and collection status. Submitted regression tests run separately where supported. The qualification included an intentionally failing submitted test that could not alter authoritative results. Unsupported changes to measured behavior remain subject to scope review. [Observed checks](observations.json)

**law-config.** The seven synthetic SQLite scenarios passed 2/7 on base and 7/7 on gold with SQLite CLI 3.45.1. Check syntax on each affected script, then measure uncontended pruning, lock release, zero and two retries, default timeout, default retry bound, and a non-lock error. Resolve configuration names, units and retry semantics from the candidate's own documentation before running behavioral checks. A reviewed mapping must cite the actual documentation and bind the candidate hash. Unresolved interfaces get no behavioral count. The historical reference adapter is confined to a verified base-equivalent qualification. All database records and home directories are synthetic. [Observed checks](observations.json)

**Tokio.** The historical generated lockfile and Rust probe were missing. The independently sealed replacement uses the official Rust 1.96.0 distribution, a newly resolved lockfile, and offline crate archives verified against that lock. Base passes all 26 frozen native tests and fails compilation with E0599 at the new API, so none of the four runtime assertions executes. Gold passes the 26 protected baseline tests, all four new runtime checks, and its 29-test upstream suite. Its shared-owner probe correctly fails compilation with E0596. A synthetic implementation that always returns None compiles and passes the 26 native tests but fails three runtime checks. The Cargo.lock and both prospective Rust probes are included. **Runner-space.** The original behavioral and output modules were unavailable. The prospective replacement uses Node 24.22.1 and 12 Linux-applicable lockfile packages verified by SHA-512. The 11 boundary checks distinguish 4/11 on base from 11/11 on gold. Both references pass 2/2 output checks, 119/119 original native checks and the module-capability check. A separate protected-home run reproduced six shared permission failures on both. The fixture measures Linux source behavior with synthetic actions and filesystem objects. Changes to checked-in distribution files require separate review. Both candidate patches applied. The TypeScript compiler rejected an unused `inspectTarget` import in each. **Personal site.** The exact five-project Playwright 1.64.0 configuration and archived held-out spec ran on the official noble Linux image. All 405 unique npm tarballs were integrity-checked, the dependency installation was offline, and both references built. ## Boundaries and reproduction

The historical pinned Linux client could not use its required device sign-in. A later signed-in full-execution route passed 224 direct and descendant boundary checks across four role profiles. The native process launcher could not create its nested namespace in any role. It produced zero scored full-workflow trials. The source-packet protocol intentionally offers no tool calls. It cannot measure repository navigation, test-driven repairs, native skill activation or the historical plugin workflow. A single repetition, fixed arm order, limited edits, source selection, cache warming, task familiarity and service variation all limit generalization. User-owned repositories remain a separate stratum.

Obtain the exact public base from the provider's legacy tarball endpoint at the full commit in the [case manifest](../cases.csv). The unhashed download is insufficient. The builder refuses an archive or rebuilt packet that differs from the frozen digest. For example, with the verified fmt archive already in task-local scratch, run from the repository root:

```sh
python3 docs/evaluations/develop-benchmark/replication/build_packet.py fmt "$FMT_BASE_ARCHIVE" > "$TASK_DIR/fmt-source.txt"
```

Run the verifier from the repository root to check the original requirements, frozen protocols, arm ledger, phase counts, usage, blind votes and patch hashes. With `--archives`, it also rebuilds each released packet from its public archive, reapplies the ordered text edits, checks the resulting file digests and reconstructs the exact submitted grading payload. Save the archive from each `base_archive_url` under the case name with slashes replaced by double hyphens, followed by `-base.legacy.tar.gz`. For example, use `fmtlib--fmt--4993-base.legacy.tar.gz` for fmt. Offline behavior results come from the separately qualified Linux graders described above.

```sh
python3 docs/evaluations/develop-benchmark/replication/verify.py
python3 docs/evaluations/develop-benchmark/replication/verify.py --archives "$ARCHIVE_DIRECTORY" --develop-repo .
python3 docs/evaluations/develop-benchmark/replication/verify.py --case-fixtures "$CASE_FIXTURE_ARCHIVE"
python3 docs/evaluations/develop-benchmark/replication/verify.py --emit-patch fmt develop
```

`--case-fixtures` checks the 27 named acceptance files inside the case archive published in issue 71. The new Tokio and runner-space fixture sources are included in this PR. The two Svelte gold-derived assertions exercise one upstream sample in DOM and hydration modes. [Original case archive](https://github.com/justinthelaw/law-config/issues/71#evidence-h) · [Svelte gold sample](https://github.com/sveltejs/svelte/tree/dc26210e41cbef4fdc241ea24a89b56b8bcfbcf3/packages/svelte/tests/runtime-runes/samples/inspect-fork-discarded)

The runtime probes consumed at least 46,607 known synthetic context tokens across the four calls with usage. A fifth qualification timed out without a usage receipt. Setup, coordination and report-author usage remain unknown.
